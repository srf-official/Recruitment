## First release checklist

1. Set the runtime configuration above, initialize the existing SQL database, and verify network access.
2. Run CI, including the Docker startup probe. Verify main contains the intended tested commit.
3. Enable the existing main-only deploy workflow and run it. The revision update preserves environment variables, secret references, resource sizing and scaling rules, and keeps the existing app URL. It changes the image and target port to 8000.
4. Verify `/readyz`, sign in, and import the private question JSON through the authenticated page. Review the flagged source answer inconsistencies and Aptitude keys before scoring a real drive.
5. Run a staging drive with synthetic names and IDs on this Azure SQL/App combination, including 50 simultaneous candidates, expiry, administrator stop, manual review and both exports. Review latency and CPU/memory. There is no SLA/capacity guarantee from the local tests.
6. After a completed verified release, fast-forward `develop` to the verified `main` commit as the backup. Do not force-reset unrelated work. Commit history remains the primary record of changes.

Do not change infrastructure sizing during an active assessment. Azure allowance and resource charges remain governed by the existing subscription; this release adds no paid resource. Keep a previously working revision and its image SHA for rollback. The deploy job checks both revision readiness and application `/readyz`; on failure inspect the revision rather than retrying blindly. No automatic rollback is performed.
